# Ownership Standard

**Document ID:** ACC-OWN-001  
**Owner:** AI/ML Engineering  
**Status:** ACTIVE  

## Purpose

This document defines how engineering ownership is proven in this accelerator.

## Ownership Principles

1. Ownership is proven through traceability, not secrecy.
2. Code must live in the approved Azure DevOps repository.
3. Commits must be attributable to the author.
4. Pull requests must describe intent, risk, and evidence.
5. Architecture decisions must be recorded in ADRs.
6. Releases must be documented.
7. Handover must be formal and auditable.

## Code Ownership Rules

| Rule | Requirement |
|---|---|
| Source of truth | Azure DevOps repository |
| Commit identity | Corporate account only |
| Pull requests | Required for merge |
| Work item linkage | Required |
| Review approval | Required |
| Release evidence | Required |
| Documentation update | Required where behavior changes |

## Prohibited Practices

- Keeping production code only on a local machine.
- Sending code as ZIP files.
- Using personal repositories for company work.
- Hiding authorship.
- Removing decision history.
- Handing over work without documentation.y
